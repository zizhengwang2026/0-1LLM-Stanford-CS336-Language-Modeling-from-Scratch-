# 第12讲 · 大模型的基本训练流程（综合 × DIY-LLM 第13章）

> **本讲位置**：把前面所有知识点串成一条线。前面分别讲了架构、并行、数据、对齐，这一讲讲"一个能用的模型，到底分几步炼出来"。
>
> **一句话定位**：现代大模型训练是一条**四阶段流水线**——预训练打底子 → （中期训练补专业能力）→ SFT 学听话 → 对齐（RLHF/DPO）学做人。每一阶段用的数据、目标、显存都不同。

---

## 一、训练全景：四阶段流水线

```
原始文本 → [1 预训练 PT] → 基座模型(Base) → [2 中期训练] → [3 SFT] → 指令模型 → [4 对齐 RLHF/DPO] → 可上线模型
```

- **预训练**：海量无标注数据，学"语言统计规律"（next-token 预测）。占 99% 算力和时间。
- **中期训练（Mid-training）**：预训练尾声混入专业/长上下文数据，补 STEM、代码等能力（现在越来越重要）。
- **SFT（监督微调）**：用高质量的"提问-回答"示范，让模型学会遵循指令、会对话。
- **对齐（Alignment）**：用人类/可验证反馈，让模型"更安全、更符合偏好"（详见第13讲）。

---

## 二、阶段1：预训练（Pre-training）

- **目标**：在网页、书籍、论文、代码（如 8B 模型约 36T tokens，通用模型 50–200T tokens）上做 **next-token 预测**，得到"续写底座"。
- **范式**：decoder-only 自回归，输入 "[自然][语言][处理]" 预测 "[是]"。
- **产物局限**：只会续写、不遵循指令、有幻觉和偏见——所以必须后面接后训练。
- **工程现实**：这一阶段最吃算力与显存，靠前面学的分布式（DP/TP/PP/ZeRO）和数据工程撑起来。

---

## 三、阶段2：中期训练 / 继续预训练

- **做法**：在**学习率衰减阶段**（WSD：warmup-stable-decay 框架）注入高质量/指令数据（如维基、UltraChat、代码 SFT）。
- **目的**：扩展能力边界，同时**防止灾难性遗忘**（忘了预训练学到的东西）。
- 现状：很多公司把"预训练"和"SFT"的界限模糊化，中期训练已成行业标配。

---

## 四、阶段3：监督微调（SFT）

- **目标**：用 10k–100k 条专家示范（QA 格式）微调底座，让它**遵循指令、拒绝有害内容**。
- **铁律：数据质量 > 数量**。李飞飞团队 s1K 用仅 1000 条高质量数据就追平 o1 级别表现。
- **数据格式**：
  - **Alpaca**：单轮 jsonl，只算"回答"部分的 loss。
  - **ChatML / ShareGPT**：多轮对话，只算 assistant 的 loss。
- **关键问题**：
  - **幻觉**：模型被强迫回答它不知道的事实 → 会编。
  - **灾难性遗忘**：学新问题忘了旧能力。
  - **安全 SFT 只需约 500 条示例**就能建立基本护栏。

---

## 五、阶段4：对齐（详见第13讲）

用 RLHF（奖励模型 + PPO）或 DPO，把模型对齐到人类偏好/正确性上。这一阶段决定"模型好不好用、安不安全"。

---

## 六、工程配置清单（通用做法，补充）

DIY-LLM 第13章侧重流程与数学，工程配置由其章节未详述，这里补上业界通用配置：

| 配置项 | 常用选择 | 说明 |
|--------|---------|------|
| **优化器** | **AdamW** | 带权重衰减的 Adam，LLM 训练事实标准 |
| **学习率调度** | cosine + warmup | 先线性升、再余弦退火；预热防初期不稳定 |
| **混合精度** | BF16 训练 / FP16 部分 | 省显存、提速，BF16 不易溢出现在更常用 |
| **分布式** | FSDP / 3D 并行 | 见第7讲 |
| **Checkpoint** | 定时存 + 可断点续训 | 训练几天几周，必须能从中断恢复 |
| **Tokenizer** | 与预训练一致 | 词表、BPE 必须和基座模型匹配 |
| **日志监控** | loss/WandB + GPU 利用率 | 见第1讲工具链，及时抓异常 |

## 七、训练中的典型问题与排查

| 现象 | 可能原因 | 对策 |
|------|---------|------|
| loss 不降 | 学习率太大/数据有问题 | 调小 lr、查数据清洗 |
| 灾难性遗忘 | SFT 数据占比或难度失衡 | 混入预训练数据、调低 SFT 比例 |
| 幻觉严重 | 强迫答未知、数据错 | 加拒答训练、提升数据质量 |
| 过优化/模式坍塌（对齐后） | 奖励模型被钻空子 | 加 KL 约束、降奖励权重 |
| GPU 利用率低 | 数据加载瓶颈/通信阻塞 | 优化 DataLoader、查并行配置 |

## 九、常见坑 & 面试可能问

1. **"预训练和 SFT 的本质区别？"** → 前者学语言统计（自监督、海量），后者学指令遵循（有监督、少量高质量）。
2. **"为什么数据质量比数量重要？"** → SFT 阶段 1k 条好数据能顶几万条烂数据（s1K 实证）。
3. **"什么是灾难性遗忘？"** → 学新任务把旧能力忘光，用数据配比 + 中期训练缓解。
4. **"为什么需要中期训练？"** → 纯预训练尾声补专业数据，既扩能力又防遗忘。
