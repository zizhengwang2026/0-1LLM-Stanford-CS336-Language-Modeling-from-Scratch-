## 一、先说这门课本身：都要做什么

CS336 全名是 "Language Modeling from Scratch"——从零开始搞语言建模。一句话概括这门课的脾气：**它不教你"怎么调别人的模型"，而是要你从最底层的 PyTorch 张量出发，亲手把一个大语言模型从头造出来。**

课上有一句很形象的话，拿操作系统课打比方：操作系统课会让你从零写一个 OS，这门课就让你从零写一个 LLM。而且有个硬规矩——**不准用现成的高层封装**（比如不能用 `nn.Transformer`、`nn.Linear` 这种"半成品"），得自己用最基础的张量运算把每一块拼出来。这么做的目的不是故意为难你，而是逼你把每个组件都搞懂：为什么这么设计、换种写法行不行、哪里是性能瓶颈。

整门课分几个大块（课程里叫 unit），串起来就是从"造单个零件"到"把工厂跑起来"：

- **Basics（基础）**：分词器 + Transformer 架构 + 训练循环。这是最小闭环——你实现这三样，就能训出一个能生成文本的小模型。
- **Systems（系统）**：怎么让模型跑得快、省显存、能堆到多张卡上。涉及 GPU kernel、分布式训练、推理优化。
- **Scaling（扩展定律）**：给定一笔算力预算，模型该做多大、数据要用多少，怎么用经验公式提前算出来。
- **Data（数据）**：怎么把网上爬来的脏数据（Common Crawl 那种原始 HTML）洗成能喂给模型的干净语料。
- **Alignment（对齐）**：训出来的基础模型还得微调、对齐，让它听话、安全、会推理。

课上有个贯穿始终的做事方法，值得记住：**每个设计决定都要拿数据说话**——benchmark（跑分）、profiling（找瓶颈）、在"算力"和"数据"两张预算表之间做权衡。不是拍脑袋选方案。

还有个挺特别的作业形式：给你一个受限的训练接口（你只能传超参进去、拿回 loss），给你一笔固定的 FLOPs 预算，让你自己决定先做哪些实验、怎么用少量数据点拟合出扩展曲线、再反推最优超参。这其实就在模拟真实世界里"算力很贵、试错机会有限"的情况。

## 二、动手前先备个"实验笔记本"：W&B（DIY-LLM 第 1 章）

（这部分中文教程放在第 1 章，因为后面所有作业都要用。）

训练一个大模型，本质上是在做一堆实验：换个不同学习率、换个 batch size、换个模型结构，看谁的 loss 降得快。实验一多，脑子就记不住了——"上周跑那个效果最好的配置到底是啥来着？"所以得有个工具自动帮你记。

**W&B（Weights & Biases）就是干这个的**：它是个专门给机器学习实验用的平台，能自动记录你的超参数、实时画出 loss 曲线、帮你管理模型版本、还能多人协作看报告。

最常用的就三板斧：

1. **`wandb.init()` 开头先初始化**，告诉它"这是一个新实验"，顺手把这次的所有超参（模型名、学习率、batch size、随机种子……）塞进 `config`。好处是以后想对比"哪次跑得好"，直接按 config 筛选就行。

```python
import wandb
wandb.init(
    project="cs336-basics",
    name="my-first-llm",
    config={"learning_rate": 2e-5, "batch_size": 64, "seed": 2026},
)
```

2. **`wandb.log()` 在训练循环里不断记指标**，比如每一步的 loss、学习率。这些会实时变成曲线图，不用自己攒 CSV 再画。

```python
for step, batch in enumerate(dataloader):
    loss = model(batch)
    wandb.log({"train/loss": loss.item(), "step": step})
```

3. **特殊环境处理**：国内服务器经常连不上外网，这时候用 `wandb.init(mode="offline")` 把日志先存本地，等有网了再 `wandb sync` 同步上去；调试时想完全关掉就用 `mode="disabled"`。

一句话：W&B 不是必须的（你用 print + 画图也能凑合），但它能省掉大量"记实验笔记"的体力活，尤其当你实验一多就特别香。

## 三、重头戏：分词器（Tokenization）

这一块 CS336 第一节课后半段和中文教程第 2 章重合度很高，我把它揉在一起讲。

### 3.1 为什么非得分词？

大模型骨子里就是一堆矩阵运算，**它只认数字，不认字**。所以任何一段文本，进模型之前都得先变成一串整数。分词器干的事，就是：**把"字符串" ↔ "整数序列"之间做一个可逆的翻译**。

为什么不直接把整句话当一个整体？因为：

- 模型需要**固定大小的输入单元**（词表里的一个个 token），就像乐高得先用标准积木块，不能上来就甩一整座城堡进去。
- 句子的"长度"是按 token 算的，而 Transformer 的注意力计算量和 token 数的平方成正比（O(N²)）。同样一段话，切得越碎、token 越多，算得越慢、越费显存。所以怎么切，直接影响效率和成本。

这里有个容易忽略的点：分词方式其实暗含了"你怎么看待这个世界"。怎么把语言切成块，决定了模型看到的"信息密度"和"语义组合方式"，进而影响它学得好不好。

### 3.2 几种切法，各有各的坑

历史上试过好几种切法，一个个看它们的问题在哪：

- **字符级（Character-level）**：一个字符一个 token（英文一个字母、中文一个字）。
  - 优点：词表极小，且没有"不认识的字"这回事（生僻字也能用基础字符拼出来）。
  - 缺点：序列太长，一个"🌍"emoji 在 UTF-8 里占了 4 个字节就是 4 个 token；而且单个字符往往没啥语义，得靠很深的网络才拼得出意思。

- **字节级（Byte-level）**：直接按 UTF-8 的字节切，基础词表固定 256 个（0x00–0xFF）。
  - 优点：最通用，跨语言、emoji、乱七八糟的编码全都能表示，彻底没有 OOV（未登录词）问题。
  - 缺点：**压缩比恒等于 1**（token 数 = 字节数），等于没压缩，序列照样长。现代很多 BPE 是"在字节级基础上再做合并"（叫 BBPE）。

- **单词级（Word-level）**：英文按空格切、中文按词切，一个词一个 token。
  - 优点：一个 "apple" 直接对应一个 ID，语义完整，压缩比高。
  - 缺点：词表爆炸——look / looks / looked 各占一个 ID，词表能涨到几十万上百万；而且新词（网络新梗、专业术语）没见过就只能标成 `<UNK>`（未知），一句话里一堆 `<UNK>` 模型就学废了。

- **子词级（Subword-level）**：折中方案，也是现在的主流。常见片段合并成 token、罕见的保留成多个小 token。
  - 优点：词表适中（三万到十万左右），OOV 极少，序列长度也合适。
  - 代表：BPE、WordPiece、Unigram、SentencePiece。GPT 系列、Llama、DeepSeek 用的都是这一派。

### 3.3 BPE：当下最流行的那个

BPE（Byte-Pair Encoding，字节对编码）是现在大模型用得最多的分词算法。它最早是 1994 年一个叫 Philip Gage 的人拿来**做数据压缩**用的，后来被用到机器翻译，2019 年 GPT-2 把它发扬光大。

**核心思想特别朴素**：先准备一段训练文本，让分词器从数据里"自己学"出词表——**出现得越多的字符组合，就越值得被压成一个 token；出现得少的，就老老实实用多个 token 表示。** 常见的词先合并，生僻的慢慢来。

具体训练步骤（以字节级 BPE 为例）：

1. **初始化**：把输入文本按 UTF-8 拆成一个个字节，每个字节是一个 token（基础词表 0–255）。
2. **统计 + 合并**：扫描全文，数出所有"相邻 token 对"出现的次数；把出现最频繁的那一对合并成一个新 token，加进词表。
3. **重复**：回到第 2 步，再找下一对最频繁的合并，直到词表达到目标大小（或合并轮数用完）。
4. **产出**：导出两个东西——`vocab`（token → id 的对照表）和 `merges`（合并规则的先后顺序，解码时要倒着用）。

编码（文字 → 数字）就反过来：先把文字切成基础单元，再按 merges 的顺序一步步合并，最后映射成 ID。解码（数字 → 文字）就是 ID 还原成 token 字符串、拼回去。

**为什么 BPE 赢了？** 因为它简单、数据驱动、压缩效果好，而且词表可控、几乎不出现未登录词。GPT-4、Llama 这些主流模型都选它，不是没道理的。

### 3.4 另外三个"兄弟"

- **WordPiece**（BERT 那一支用的）：思路和 BPE 像，但选"该合并哪一对"时不是看出现次数最多，而是看**合并后能让整段文本的似然概率提升最大**的那一对。更克制，适合做掩码语言模型。
- **Unigram**（T5、mT5 用的）：基于概率语言模型，先用一个大词表，再用 EM 算法反复迭代、**剪掉那些出现概率最低的子词**。对低频词和多种语言比较友好。
- **SentencePiece**（LLaMA、DeepSeek 用的）：不是新算法，而是个**语言无关的框架**，内置了预分词，还把空格用特殊符号 `▁` 记下来，能直接用 BPE 或 Unigram 来训练。端到端支持多语种，工程上很方便。

一句话区别：这四个没有"绝对最好"，看你的语料、任务和词表大小来选。BPE 最流行，SentencePiece 是多语种工程落地的好选择。

### 3.5 几个绕不开的小细节

- **特殊 token**：像 `<PAD>`（补齐长度）、`<UNK>`（未知）、`<BOS>`/`<EOS>`（句子开头/结尾）、`<CLS>`/`<MASK>`（分类/掩码）这些，是训练时固定下来的"保留字"，不参与上面的统计合并，保证编解码稳稳当当。
- **压缩率**：定义是"原始 UTF-8 字节长度 ÷ token 数量"。字节级恒为 1.00（没压缩）；字符级约 1.54；BPE 能到约 1.82（数据驱动压得最狠）。**压缩率越高，同样一个上下文窗口里能塞进的信息越多**，越能缓解"上下文长度不够"的尴尬。

## 四、这一篇记住这几句话就够了

1. CS336 的脾气体现在"从零造、不准用现成封装、每个决定拿数据说话"，整门课串起 Basics→Systems→Scaling→Data→Alignment 五大块。
2. W&B 是帮你自动记"实验笔记本"的工具：init 开实验、log 记曲线、offline 应对无网环境。
3. 分词的本质是"文字 ↔ 数字"的可逆翻译；切法从字符/字节/单词一路演进到子词，是为了在"词表大小、OOV、序列长度"之间找平衡。
4. BPE 靠"高频组合先合并"从数据里学词表，当下最流行；WordPiece / Unigram / SentencePiece 是思路略有不同的三兄弟。
5. 分词不是小事——它怎么切，直接决定模型看到的"世界"长什么样，进而影响最终表现。
