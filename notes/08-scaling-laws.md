# 第8讲 · 扩展定律 Scaling Laws（CS336 L9/L11 × DIY-LLM 第9章）

> **本讲位置**：CS336 **Scaling（扩展）** 块的核心。前面讲"怎么造、怎么跑"，这一讲讲"造多大的、喂多少数据、花多少算力最划算"——这是用钱和资源做决策的尺子。
>
> **一句话定位**：扩展定律告诉我们——**模型性能随规模呈可预测的幂律提升**。先在小模型上量出规律，再外推到大模型，避免闭着眼睛烧几百万美元。
>
> **难度评级：🟠 偏难（需要一点数学直觉）**。它不像分布式/对齐那样概念链条长，但要求你接受"双对数坐标上的直线"这种抽象，并理解 Kaplan 与 Chinchilla 的推导差异。CS336 作业 A3 就是"拟合 scaling law 预测配置"，做对前提是吃透这一讲。

---

## 🔤 先扫盲：重点术语大白话

| 术语 | 大白话 |
|------|--------|
| **扩展定律 Scaling Law** | 模型越大/数据越多/算力越多，loss 越低，且呈可预测的幂律。 |
| **幂律 Power Law** | 一种"翻倍投入只换一点点回报"的递减关系，画双对数是直线。 |
| **参数量 N** | 模型里可学习的权重总数。 |
| **数据量 D** | 训练用的 token 总数。 |
| **算力 C** | 训练总共花的浮点运算量(FLOPs)。 |
| **Chinchilla 最优** | DeepMind 结论：每个参数配约 20 个 token 最划算(计算最优)。 |
| **Kaplan 定律** | 早期结论：预算里更多该砸给"更大模型"(N 弹性 > D)。 |
| **C = 6ND** | 训练总算力 ≈ 6 × 参数量 × token 数（铁律）。 |
| **训练最优** | 花同样算力，最终 loss 最低的配置。 |
| **推理最优** | 部署时更便宜的配置（常过训练小模型）。 |
| **过训练 Over-training** | 给小模型喂远超 20:1 的数据，换更低推理成本。 |
| **涌现能力 Emergent** | 常说"忽然会了"，但多为评测指标假象；scaling law 本身是平滑的。 |

**记住这条主线**：给定预算 C，用 C=6ND 在 N(模型) 和 D(数据) 间找最优配比；要准用 Chinchilla 20:1，要省用过训练。

---

## 零、先建立直觉："越大越聪明，但越来越贵"

想象健身：练得越久（投入越多），身体越好（loss 越低），但**每多练一小时，收益越来越小**。Scaling law 就是把这种"边际递减"用一条数学直线定量画出来——而且它神奇地**在模型从 100M 到 100B 都基本成立**，所以你能用便宜的小实验预测昂贵的大家伙。

---

## 一、什么是"扩展定律"

观察到一个稳定的现象：当**参数量 N**、**训练数据量 D**、**算力 C** 变大时，模型的**损失（Loss）按幂律下降**。画在"双对数坐标"上是一条直线。

- 形式：`Loss ∝ N^(-α) = D^(-β) = C^(-γ)`，α/β/γ 是常数（语言模型 α ≈ 0.076 量级）。
- 含义：规模越大越准，但**边际收益递减**（每多一倍算力，loss 只降一点点）。
- 理论渊源：统计学习里 VC 维给出的泛化误差上界 `ε ≤ ε* + O(√(d/m))`（误差随样本 m 以 1/√m 下降），是"缩放定律"的最早思想原型。

> **为什么必须画双对数？** 因为幂律 `y = a·x^k` 取对数后变成 `log y = log a + k·log x`——一条直线。斜率 k 就是"扩展性"：k 越陡（负得越多），说明加资源越有用。如果画在普通坐标上，就是一条弯弯曲曲的递减曲线，看不出规律。

---

## 二、Kaplan 2020：最初的定律（"把模型做大"）

OpenAI 2020 年论文《Scaling Laws for Neural Language Models》系统给出：性能与 C、N、D 都呈幂律。

关键结论（在**固定算力预算**下）：

- 最优参数量：`N_opt ∝ C^0.73`
- 最优数据量：`D_opt ∝ C^0.27`

也就是说，Kaplan 认为**预算里大部分应该砸在"更大的模型"上**，数据相对少一点。参数量最优公式近似 `L(N) = (N_c / N)^0.076`。

> GPT-3 就是按这个思路：175B 参数，但只喂了约 300B tokens（约 **2 tokens/参数**）。
>
> **直觉理解 0.73 vs 0.27**：给定一倍算力，Kaplan 说把 73% 的增量给"更大的模型"、27% 给"更多数据"。模型规模的幂次弹性远大于数据。

---

## 三、Chinchilla：修正为"数据也要大"（转折点）

DeepMind 2022 年发现 Kaplan 的结论是**因为实验数据不够多**导致的偏差。他们做了系统实验，得到"计算最优"定律：

- **D / N ≈ 20**（约 **20 tokens / 每个参数**）
- 同样 1.4×10^23 FLOPs 预算，训一个 **70B 模型 + 1.4T tokens**，效果**超过** GPT-3 175B（后者只用 ~350B tokens）。

### 3.1 公式 C = 6ND 从哪来（面试常考）

训练一个 token 大约要 **6 × 参数量** 次浮点运算：

- **前向传播**：每个参数对每个 token 做一次乘加 = 2 FLOPs；
- **反向传播（对激活）**：约为前向的 2 倍 = 4 FLOPs；
- **反向传播（对权重，算梯度）**：约 2 FLOPs；
- 合计 ≈ **6 ND**（N 参数、D 训练 token 数）。

> 所以"算力预算 C"和"(模型大小 N, 数据量 D)"被 `C = 6ND` 这条铁律绑在一起。已知任意两个就能算第三个。

### 3.2 Chinchilla 是怎么推出来的

把 `C = 6ND` 代入损失公式 `L = E + A·N^(-α) + B·D^(-β)`，在固定 C 下对 N、D 求最小，得到最优时 `N ∝ D ∝ √C`，且比值 `D/N ≈ 20`。

| 模型 | 参数 | 训练 tokens | tokens/参数 |
|------|------|------------|-----------|
| GPT-3 | 175B | ~350B | ~2 |
| Chinchilla | 70B | 1.4T | 20 |
| LLaMA-65B | 65B | ~1.4T | ~22 |
| Llama-2-70B | 70B | ~2T | ~29 |
| Mistral-7B | 7B | ~0.8T | ~110 |
| Llama-3-70B | 70B | ~15T | ~215 |

> **注意一个反直觉事实**：Chinchilla 给的是"训练时最优"，但后面 Llama-3 用到 215 tokens/参数——比 20 大了一个数量级。这不是打 Chinchilla 脸，而是"推理最优"在起作用（见第四节）。

## 四、参数 / 数据 / 算力 三者怎么权衡

固定一个量，调另外两个，存在唯一的"最优组合"：

- **固定算力 C**：有一个最优的 (N, D) 配对。钱多就造大模型 + 多数据；钱少时小模型 + 适量数据反而更优。
- **固定模型 N**：数据越多越好，但**重复数据超过 ~4 个 epoch 收益骤减**，约 40 epoch 后基本没用（模型开始"死记"而非"学习"）。
- **联合缩放公式**（简化）：`Loss = E + A·N^(-α) + B·D^(-β)`，E 是不可约误差（即便无限大模型也达不到的底线，比如语言本身的噪声）。

### 4.1 训练最优 vs 推理最优（过训练）

Chinchilla 给的是**训练最优**（花同样的算力，最终 loss 最低）。但现实中你还关心**推理成本**（每生成一个 token 要多少钱）：

- 训一个小模型 + **远超** 20:1 比例的数据（叫**过训练 over-training**），虽然训练时 loss 不是最低，但**推理时便宜得多**（小模型跑得快、显存小）。
- 所以业界实际偏好"过训练"：Mistral-7B 用 110 tokens/参数，Llama-3 用到 215 tokens/参数——用更多数据把小模型"喂透"，换更低的服务成本。

> **一句话**：**训练最优看"最准"，推理最优看"最便宜"**。选哪个取决于你是发论文（要准）还是做产品（要省）。这也是为什么同一个 7B，Mistral 敢喂 0.8T 数据——它瞄准的是"部署便宜"。

## 五、扩展定律怎么用来指导选型（动手算）

**一个简化算例**：假设你有 8 张 A100（约 3.5 petaFLOP/s 每卡 × 8 × 训练时长），预算算力 C ≈ 1×10^21 FLOPs（示意量级）。

1. 用 Chinchilla `D/N = 20` 和 `C = 6ND` → `C = 6N·(20N) = 120 N^2` → `N = √(C/120)` ≈ √(8.3×10^18) ≈ **2.9B 参数**，`D = 20N ≈ 58B tokens`。
2. 若你想"推理更省"而过训练到 D/N=100，则 `C = 6N·100N = 600N^2` → `N ≈ 1.3B`，`D ≈ 130B tokens`——更小的模型、更多的数据，推理更便宜。

> **真实用法**：先用 100M 级小模型把超参（学习率、batch、深度/宽度比）调到最优，**再外推到大模型**（μP 等方法让小模型搜到的超参能迁移），省大量试错钱。Cerebras、MiniCPM、DeepSeek 都用这套方法论。

## 六、关于"涌现能力"（澄清一个常见误解）

很多人把"模型突然会做某件事"叫**涌现能力（emergent abilities）**，并以为是扩展定律的神奇效应。需要澄清：

- 严格意义上的扩展定律描述的是**平滑的幂律下降**，不预言"突变"。
- 很多所谓"涌现"其实是**评测指标（如准确率台阶）造成的假象**——换一个平滑指标，能力其实是连续增长的。
- 所以：别把"涌现"当成 scaling law 的主效应，它就是背景概念。真正的"突变"多来自**架构/数据/训练方法的改变**，不是单纯堆规模。

## 八、常见坑 & 面试深挖

1. **"Chinchilla 的 20:1 是什么？"** → 每个参数配约 20 个训练 token，是计算最优的数据/参数比。
2. **"为什么 GPT-3 按 Kaplan 只用了 2 tokens/参数？"** → 当时定律高估了模型规模的重要性，数据喂少了，所以被 Chinchilla 反超。
3. **"C = 6ND 哪来的？"** → 前向 2ND + 反向(激活) 2ND + 反向(权重) 2ND ≈ 6ND（每 token 每参数约 6 FLOPs）。
4. **"训练最优和推理最优有什么区别？"** → 前者看 loss 最低（Chinchilla 20:1），后者看部署便宜（过训练到 100:1+，如 Llama-3）。
5. **"涌现能力是真的吗？"** → 很多是评测指标造成的假象，扩展定律本身是平滑的。
6. **"为什么固定 C 时 N 和 D 同比缩放？"** → Chinchilla 在 C=6ND 约束下最小化损失，最优解正好是 N∝D∝√C。
