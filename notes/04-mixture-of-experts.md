# 第 4 篇笔记：混合专家模型（MoE）

> 来源合并：Stanford CS336 第 4 讲（Mixture of Experts）+ Datawhale《DIY-LLM》第 5 章（混合专家模型）
> 这一讲解决一个"既要又要"的矛盾：**想让模型参数更多、容量更大，但又不想让每次计算量也跟着线性暴涨。** MoE 就是答案。

## 一、MoE 是什么

MoE（Mixture of Experts，混合专家）是一种**稀疏激活**架构。直观比喻：

> 想象一个图书馆，里面有很多"专家书架"（专家网络）。读者（输入 token）来了，由一位"图书管理员"（路由器 / 门控）指引，只去少数几个相关书架找书——而不是把整个图书馆都翻一遍。读者最终能用到全部知识，但每次只激活一小部分书架。

具体做法：把 Transformer 里原本**单个的 FFN（前馈网络）换成多个并行的"专家"FFN**，再加一个路由器（Router / Gating Network）决定每个 token 该交给哪几个专家处理。一次前向里，每个 token 通常只激活 Top-1 或 Top-2 个专家，其余专家"挂机"不参与计算。

## 二、为什么用 MoE（核心卖点）

传统稠密模型（Dense）：每个 token 流经全部参数，计算量随参数线性增长。

MoE 的魔力在于：**用几乎不变的 FLOPs，把参数规模撑大好几倍。**
- 因为专家是"稀疏激活"的——参数总量很大，但每次只算一小部分。
- 专家还天然适合分布到不同设备（路由器把 token 发到对应设备的专家），等于自带一种"专家级并行"。

所以它成了当下大模型（Mixtral、DeepSeek 系列、Qwen-MoE 等）的关键架构选择。一个常见说法：MoE 让"模型容量"和"单次计算成本"解耦了。

> 注意边界：研究表明 MoE 在**参数大、数据多、算力足**时优势最明显；小规模或资源受限时，可能还不如稠密模型。它不是万能药。

## 三、稀疏激活 vs 稠密

- **稠密（Dense）**：单一 FFN，每次前向所有参数都参与，计算量 ∝ 参数量。
- **稀疏（MoE）**：多专家，每次只 Top-K 个被激活，未选中专家的权重直接置零、不计算。参数巨大但**激活参数量**小。

一个实验参考（OLMoE）：从零训练 Top-K(TC) 路由的 MoE，约用 25% 的稠密训练量就能追上 upcycled（从稠密转 MoE）版本；而 Expert-Choice(EC) 路由要 120%。差异主要来自路由策略。

## 四、专家（Expert）与 FFN 的关系

MoE 就是把原 Transformer 里的稠密 MLP/FFN 换成多个"专家网络"，**每个专家本身就是一个独立的 FFN**（`Linear → 激活 → Linear`）。专家主要负责特征变换和知识存储，通常占 Transformer 很大一部分参数。

进阶设计：
- **共享专家（DeepSeekMoE）**：在路由专家之外，保留几个"常驻专家"捕捉通用知识，降低路由专家的冗余。
- **细粒度专家分割**：把大 FFN 拆成更小的 FFN（比如 0.25 倍），增加专家个数，分工更细。

## 五、路由机制（Routing / Gating）

路由器决定"每个 token 交给哪些专家"。核心公式：`y = Σ_{i∈Top-K} Gᵢ(x) · Eᵢ(x)`，其中 `Gᵢ` 是门控权重，`Eᵢ` 是专家输出。

步骤：
1. **打分**：`h(x) = x · Wg`（Wg 是可学习投影），得到每个专家的匹配分数。
2. **稀疏化**：取分数最高的 K 个专家，softmax 归一化，其余置零。

两种主流路由形式：
- **TC（Token Choice，token 选专家）**：每个 token 挑 Top-K 专家——语义完整，但容易"偏科"（少数热门专家爆满）。
- **EC（Expert Choice，专家选 token）**：每个专家挑 Top-K token——负载天然均衡，但可能丢弃部分 token。

非学习路由（如哈希路由 LSH）也能用：固定哈希函数映射，天然均衡、无需训练，但语义弱。

可学习路由的坑：浅层 token 表示不稳定导致梯度高方差；条件计算下梯度不对称（专家只在被选中时更新，路由器却一直更新）→ 训练不稳定。

## 六、负载均衡与辅助损失

**问题**：少数"热门"专家处理绝大部分 token，冷门专家闲置（"死亡专家"），导致偏科、训练低效。

解决策略：
- **辅助负载均衡损失（Auxiliary Loss）**：在训练 loss 里加一个正则项，鼓励各专家接收的 token 量均匀（Switch Transformer 采用）。
- **容量控制 + 专家容量（Expert Capacity） + 溢出丢弃**：每个专家设最大处理 token 数 `C = ⌈(N/E) × capacity_factor⌉`，超容量的 token 不走 FFN、只走残差（不产生该专家梯度）。这牺牲了被丢 token 的语义，但让计算量可预测。
- **动态无辅助损失均衡（Loss-Free Balancing）**：给专家加一个基于历史负载的 bias 来调分数，不引入额外 loss。
- **DeepSeekMoE 具体**：专家级平衡损失 `L_ExpBal` + 设备级 `L_DevBal`（多设备通信平衡）+ 共享专家。

## 七、MoE 的训练与推理特点

- **训练**：稀疏路由引入离散决策，梯度估计方差高；浅层表示非平稳，路由器难训。常见不稳案例（DeepSeek V4 遇 Loss Spike）：用"前瞻路由"（解耦路由更新、缓存分配）+ SwiGLU 钳制（[-10,10]）来稳定。
- **推理**：只激活少数专家，FLOPs 恒定；专家可分布多设备，并行高效；显存占用因激活少而优。DeepSeek V3 用 FP8 传激活、BF16 算关键部分保稳定。
- **微调**：Kimi-K2（1.04T 参数、激活 32.6B）用 LoRA+RL，GPU 成本降到约 10%，大基座+小 LoRA RL 优于小模型全参 RL。

## 八、代表模型

- **Switch Transformer**：Top-1 路由、Router Z-loss、超容量丢弃。
- **DeepSeek 系列**：
  - **DeepSeekMoE**（V3 基础）：细粒度专家分割（N→mN 小专家，激活 mK 个）+ 共享专家 + 辅助损失 + FP8 通信。
  - **DeepSeek V4**：浅层引 3 层 Hash MoE（非学习）替 Dense；前瞻路由 + SwiGLU 钳制。
  - **DeepSeek-R1**：展示 MoE 高性能推理潜力。
- **Mixtral**、**Qwen1.5-MoE**（upcycling 稠密为 MoE）、**OLMoE**（从零高效追稠密）、**Kimi-K2**（LoRA+RL 混合）等。

## 九、这一讲记住这几句话就够了

1. **MoE = 把单个 FFN 换成多个专家 + 一个路由器**，每个 token 只激活少数专家——**稀疏激活**。
2. **核心卖点**：参数可以很大（容量大），但每次计算量基本不变（FLOPs 不涨），把"容量"和"成本"解耦。
3. **路由**决定 token 去哪：`y = Σ Gᵢ(x)·Eᵢ(x)`；TC（token 选专家）语义好但易偏科，EC（专家选 token）均衡但会丢 token。
4. **负载均衡是头号难题**：靠辅助损失 / 容量上限丢弃 / 无辅助损失均衡来解决"死亡专家"。
5. **推理优势明显**：激活少 → FLOPs 恒定、显存省、专家可分布式；DeepSeek 用细粒度专家+共享专家把这条路走到极致。

> MoE 是"在固定算力下扩大参数"的王牌。下一篇（第 5 讲）回到硬件：GPU 到底怎么算、怎么优化，才能把这些架构真正跑快。
